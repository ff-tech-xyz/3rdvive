# Project state

2026-09-26: First test implementation on `build-v1.0` after the scaffold. Eight incremental commits added loader-shared config, perspective preservation, headset-relative camera positions with wall clipping, front-view rotation, and local-avatar rendering. Fabric and NeoForge both compile and reach the main menu with Vivecraft 26.2-1.3.15 under a virtual display. The Fabric mixin export confirms the two VR-transition camera-type invocations are intercepted; headset rendering and the full VR checklist remain unverified. An initial Fabric launch failed on mixin priority and an initial NeoForge launch failed because config read `Minecraft.getInstance()` before construction; both faults were corrected and each loader subsequently reached the menu. Do not describe this as a release or as hardware-tested.

2026-09-27: Replaced camera relocation and separate view-matrix rotation with render-pass-only `VRData.getEye` substitution. The render copy alone supplies per-eye third-person poses while `vivecraft$setupRVE` still sees the real eye; headset/controllers, sound listener and tick-time camera remain unmodified. One frame computes a head-center pivot, the vanilla 26.2 camera-distance expression (scale/vehicle), and 8-ray clipped zoom; first-person limb scaling, face overlays and nametag correction are disabled in third-person passes. `distance=0` now uses vanilla, and an existing `4.0` config remains an explicit override. Fabric and NeoForge Gradle builds passed; both revised clients reached the main menu under Xvfb without a mixin crash. Headset behavior, including front stereo and all hand/controller interactions, remains untested. This is a headset test candidate, not a release.

2026-09-27: Added character-anchored third-person tracking on top of the eye substitution. The lock ignores menu overlays; it cancels physical roomscale walking, pins world-space poses at tick start/end and pins the render copy to the interpolated player eye each frame. The shared head pivot drives both the anchor and camera. The start pin runs before Vivecraft captures pose history. Leaving the lock restores Vivecraft's normal room origin before building the next tick's poses when eligible, deferring the restore if Vivecraft's sneak counter would refuse it. Fabric and NeoForge builds passed after the exit-ordering adjustment. Each loader started under Xvfb with 3rdVive and Vivecraft loaded and reached resource/renderer initialization without a mixin crash; the bounded runs ended at their 110-second and 55-second timeouts respectively. VR poses and the full headset checklist remain unverified; a flat-screen launch cannot exercise the locked path.

The branch is pushed only when a testable build is ready for Elijah. `main` remains untouched; Elijah decides merging and releases.
